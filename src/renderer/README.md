# Renderer

The React app. It has no Node access: everything outside the page goes through the typed `MangaboundBridge` interface.

- `app.tsx` is the desktop entry: it reads `window.mangabound` and either supplies it to `WorkflowApp` or shows startup recovery instructions. A missing preload is an error, not a scaffold preview. It wraps `WorkflowApp` in `app-settings-provider.tsx`, which reads what a person decided about the app (ADR 0052) and gives everything under it the language and its messages; nothing is drawn until they are read, so nothing is drawn in a language that is about to change.
- `workflow-app.tsx` holds the state (the queue, the options, the screen and its editing target) and wires the screens together. Navigation is one discriminated union: the library screen carries its queue row id; mapping and details carry either an input id or a library row id and title together. Queue, options, running and results carry no stale editing selection. Rows and drafts stay in the queue reducer, not in navigation. Its bridge is a required prop; it never reads `window.mangabound`, so another entry can supply an implementation of the same interface. It is the one place that calls the bridge for a run, and it begins the queue with the main process at the click and ends it in a `finally` (ADR 0065). It applies the pure decisions from `domain/run-report.ts`: per-input and per-title results, cancellation, omitted rows and completed rows. The bridge calls, session release and React state updates stay here; the report owns none of them. The lifecycles of the tools, the pending books, sharing and the kept settings live in `hooks/`; the progress state stays here too: a progress event was measured and costs little even for a very large queue (audit finding 16).
- `screens/` are whole steps: the queue, a library's titles, the title, author and language of an item, conversion options, the running item, the results. Each begins with `ScreenHeader` (`components/shared/`), which puts focus on the title when the screen opens and draws no ring on it (ADR 0072). `ConversionOptionsScreen` composes the existing settings editor and reset confirmation and focuses its heading only on entry, not on every settings update. The workflow supplies choices and callbacks, retaining persistence, reset behavior and single-book constraints; the screen does not call the bridge.
- `components/` are grouped by what they are for: `mapping/` (the volume editor), `queue/` (the rows and the drop area), `settings/` (the process steps, the mangapress options, reset, and the dialog behind the gear on the title bar: `app-settings-tabs.tsx` is its list of tabs, one for each responsibility (Interface, Updates, then About, ADR 0054 and 0055), and adding a tab is adding an entry there; the box has a fixed size with the list of tabs beside the panel, `app-settings-nav.tsx`, ADR 0055), `sharing/` (the one Share panel and the button that opens it), `shell/` (the title bar), `shared/` (notices and other compositions used across screens), and `ui/` (the design-system primitives: button, input, tabs, menu, and so on).
- `assets/` is the logo for the title bar and the About tab (48px and 192px, lossless WebP), embedded in the bundle as `data:` addresses; `assets/README.md` at the root says how they are made.
- The look is a theme (ADR 0066, ADR 0067): `styles.css` has one block of variables for each theme (dark and light), selected by the `data-theme` attribute that `AppSettingsProvider` puts on the page, and a component reads them through the tokens without knowing which theme it is in. The Interface tab chooses it, or chooses to follow the system, which `useResolvedTheme` comes to with the page's own `prefers-color-scheme`, kept up to date as the system changes (ADR 0070); Storybook has a Theme toolbar that sets the same attribute, and `test:stories` runs every story in the default theme and again in the light one, with the accessibility check in both.
- A checkbox with its words is a `CheckRow` (`components/settings/check-row.tsx`, ADR 0071): the box centered on the line of its title (what a step uses, a description or a reason is a note under it), and, beside a field with a label in two columns, in line with that field's control. The steps of the queue and the choices of the options page use it; the header of a field is set in its label's own size, so a line of 20px is what everything is aligned to.
- `lib/` is pure helpers, under the 100% coverage gate; `lib/shortcuts.ts` says the keys of a shortcut for each system, how they are written and announced (ADR 0064); `lib/queue-signal.ts` tells the main process that a queue has begun and ended, and goes on when it cannot (ADR 0065).
- What the window says is in `src/i18n/` (ADR 0052), not here: the components read it through `useMessages` (`hooks/use-messages.ts`), and without a provider a component speaks English, so a story or a test can draw it on its own. What the main process and the domain say by code (ADR 0053) is written by `useSay()` (`useSayLater()` for an effect, whose function does not change with the language), and `lib/said-error.ts` is the error that carries such a message through code that throws.
- `hooks/` is React hooks: ones shared across components, such as `useClickOutside`, and the lifecycles the workflow component hands off to keep itself small, such as `useToolchain` (the status of the bundled tools and the devices they can convert for) `usePendingRuns` (the conversions whose books are waiting to be saved or shared) `useSharing` (the Share panel: the folder, the network addresses, whether sharing runs, and starting and stopping it) and `useKeptSettings` (the choices kept between sessions, restored once and saved when they change; ADR 0014), `useAppSettings` (what a person decided about the app, such as its language, read once and kept as it changes; ADR 0052), `useAppInfo` (what the About tab shows of the app: its version and system, and the way to open a place in the system browser by name; ADR 0054), `useWorkingSpace` (what is left on the drives the app works on, asked when the queue is shown and when the window is looked at again, for the warning above the Process button; ADR 0060). The Processing tab (`components/settings/processing-tab.tsx`) also holds `waiting-books.tsx`: what waits, and the clean-up that asks before it deletes (ADR 0061); `AppSettingsMenu` is controlled by its own state, so Ctrl+, (Cmd+, on macOS) opens what the gear does (ADR 0064), and tells `onClose` so the queue reads its ready books again and `useMessages` (what the window says, in its language). They touch the DOM and React's own lifecycle, so they are covered by component tests instead of the node-environment unit gate `lib/` uses.
- `styles.css` holds the design tokens (ADR 0002). The default theme is a graphite dark with a lavender accent, and the light one the same hues turned over; nothing else defines a color.

Every component and screen is meant to have a Storybook story next to it, with the accessibility check running on each one; `docs/audit-2026-09.md` tracks the current gaps.
