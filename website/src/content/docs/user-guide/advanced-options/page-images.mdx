The **Page images** section of [Advanced conversion options](../../output-profiles/#advanced-conversion-options) is about the file each page is saved as, not about how the page looks: the same drawing, in a bigger or smaller file, with its tones kept or reduced. The numbers below are the sizes of the files mangapress wrote for one page of _Pepper&Carrot_, 992 × 1373 pixels, converted for the Kindle Paperwhite 6, as in the other pages of this guide.

## Page format

- **JPEG, full tone**, the starting choice: each page is a gray JPEG that keeps all 256 tones. It is not dithered. `--forcepng` is not given.
- **PNG, reduced to the screen's grays**: each page is reduced to the grays the device's screen can show, with the dither Pillow uses (Floyd–Steinberg), and saved as a PNG without loss. That is 16 grays for every profile but two: Kindle 1 has 4, Kindle 2 has 15. The file is a palette PNG, which stores 4 bits per pixel (2 for Kindle 1). `--forcepng`.

## Keep all 256 grays

Skips the reduction: the page keeps every tone, and is saved as an 8-bit gray PNG without loss. It is the biggest of the gray files in the table above, about three times the JPEG, and the page is as smooth as the JPEG in the picture. It applies only to PNG pages, so it is dimmed with **JPEG, full tone**. `--noquantize`.

## 8-bit PNG

For readers that cannot open the more compact palette PNG. The pixels are the same, the 16 grays, and the file is an 8-bit gray PNG, which takes more room: the third row of the table, against the second. It is dimmed unless **Page format** is PNG, while **Keep all 256 grays** is on (the page is already 8-bit), and in a PDF (always 8-bit). `--pnglegacy`.

## Color pages as PNG too

Color is chosen in [Color and tone](../color-and-tone/); this is about the file a color page is saved as. A page kept in color is saved as an RGB JPEG, and stays one even when **Page format** is PNG: **PNG** only reduces the grays of the pages that are gray. **Color pages as PNG too** saves the color pages as PNG as well, without loss, and it is the one option here that changes the size by an order of magnitude: in the last three rows of the table the color JPEG, the same with PNG pages and the color PNG are 293 KB, 293 KB and 2 MB for the same page, seven times as much. It is dimmed unless color pages are kept in color and **Page format** is PNG. `--force-png-rgb`.

## Use the images as they are

Packages the pages untouched: nothing is cropped, resized, turned to gray or saved again. For a CBZ, the file in the book is the input's file byte for byte; the table compares it with the converted page:

<OptionSizes id="as-they-are" />

The page above is already a JPEG with more tones than the converted one needs, so the untouched file is the bigger of the two, and it is 992 × 1373 pixels, not the screen's 1272 × 1696. The reading order, the webtoon cut and the two-page view still apply, and an EPUB's cover is still made from the first image, so for an EPUB, **Color pages** and **JPEG quality** still decide it. An EPUB cannot hold a BMP page unchanged: the conversion is refused and says to turn the option off or choose CBZ.

While it is on, the app dims everything that would change an image: **Page format** and the three PNG options, **Gamma**, **Reduce rainbow effect**, the cropping, size and border options and **Autocontrast**; for a CBZ or PDF, **Color pages** and **JPEG quality** too. `--noprocessing`.

## Options and flags

- **Page format**: `--forcepng` for PNG; none for JPEG.
- **Keep all 256 grays**: `--noquantize`.
- **8-bit PNG**: `--pnglegacy`.
- **Color pages as PNG too**: `--force-png-rgb`.
- **JPEG quality**: `--jpeg-quality`, from 1 to 100.
- **Use the images as they are**: `--noprocessing`.
