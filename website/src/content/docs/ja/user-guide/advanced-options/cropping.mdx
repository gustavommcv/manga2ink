トリミングは、ページを画面に合わせる前に、ページの何もない余白を切り落とします。そのぶん、絵は大きくなります。設定は[詳細な変換オプション](../../output-profiles/#詳細な変換オプション)の**トリミング**セクションにあります。**ページのトリミング**は、**ウェブトゥーンの縦長ストリップ**と**画像をそのまま使う**のときは、理由とともに薄く表示されます。3 つの数値（**トリミングの強さ**、**最低限残す範囲**、**残す余白**）はそれに従い、**無効**の間も薄く表示されます。**コマ間のトリミング**が薄く表示されるのは、**画像をそのまま使う**のときだけです。

次の 2 つのセクションの画像では、変換したページが左にあり、残る部分は青緑色で囲み、切り落とす部分はピンクで塗っています。右は、画面に出るときのページです。

## ページのトリミング

既定は**余白とページ番号**です。

    'margins-and-page-numbers':
      'マンガのページで、余白がピンクで塗られ、残る部分が青緑色で囲まれています。その隣は画面に出るときのページで、余白がなくなり、絵が大きくなっています。',
  }}
/>

ページは画面と同じ形なので、トリミングを**無効**にすると余白が残り、そのぶん絵は小さくなります。トリミングをオンにすると、余白がなくなり、絵が大きくなってその場所を埋めます。

- **無効**は、ページをそのまま画面に送ります。
- **余白**では、mangapress が絵のある場所を探します。ページをグレーにし（背景が暗いときは反転します）、階調を引き伸ばして、少しぼかし、しきい値より明るいものをすべて紙として数えます。残ったものを囲む箱が絵で、ページはそこまで切られます。どのページも、上下左右それぞれで幅や高さの 10% を超えては切られないので、とても広い縁のあるスキャンは、それを超える分が残ります。
- **余白とページ番号**は、同じ処理をしたあと、箱の下の縁のすぐ上にある細い帯をもう一度見ます。そこに、1 桁から 3 桁の数字くらいの小さな暗い形がちょうど 1 つだけあれば、ページはその形のすぐ上で切られます。2 つ以上ある場合や、大きすぎる場合は、絵だと見なされて、そのままになります。

上のページにはページ番号がないので、**余白**は**余白とページ番号**と同じ結果になります。`--cropping` は `disabled`、`margins`、`margins-and-page-numbers` を受け付け、短縮形は `-c` です。

## トリミングの強さ

既定は 1 で、アプリは 0 から 10 まで受け付けます。この値が、ページを判定するしきい値を決めます。255 を白とする目盛りで、**240 − 64 × 値**です。1 のときのしきい値は 176 で、それより明るい階調はすべて紙です。値を上げるとしきい値が下がり、より暗い階調も紙として扱われるので、トリミングは陰影や細い線にまで及びます。

画像は、1 枚のページについて、それぞれの値で残る部分を囲んでいます。囲みの色の隣に、その値が書いてあります。0、1、2、3 の囲みはほとんど同じで、3.75 がいちばん狭く、3.76 では何も切られないため、その破線の囲みはページ全体です。

大きければよいとは限りません。3.75 ではしきい値が 0 になり、純粋な黒だけが絵として数えられます。そのためトリミングは最も黒い線にぴったり張りつき、ページに食い込んで、ここでは幅 887 ピクセルまで切られます。3.76 以上にすると、しきい値は 0 を下回ります。絵として数えられるものがなくなり、mangapress は何も見つけられず、ページはトリミングされません。つまり、3.75 を超える値は、トリミングを強めるのではなく、オフにします。スキャンの余白がグレーなら、それ以上に上げる前に、2 を試してください。

`--croppingpower` で設定します。

## 最低限残す範囲

既定は 0% で、アプリは 0 から 100% まで受け付けます。mangapress は、切ったあとのページがページの面積のこの割合以上を保つ場合にだけトリミングし、そうでなければページをそのままにします。

<OptionSizes id="cropping-minimum-sizes" />

このページのトリミングは 80.1% を保つので、最小値 80 なら許可され、81 なら拒否されます。ほとんど空白のページを守るために使います。そうしたページでは、検出された絵がページのごく一部で、そこまで切ると、数本の線が画面いっぱいに拡大されてしまいます。最小値を 70 にすると、ページの 70% 未満しか残らないトリミングは行われません。`--croppingminimum` で設定します。

## 残す余白

既定は 0% で、アプリは 0 から 100% まで受け付けます。10% の上限のあとで、トリミングはこの割合だけ戻されるので、余白が少し残ります。50% なら、取り除かれるはずだった分の半分が残り、100% なら何も取り除かれません。2 枚目の画像で、破線の囲みは 0% のときに切っていた位置です。

## コマ間のトリミング

既定は**無効**です。このオプションが取り除くのは、ページのまわりの余白ではなく、コマ*の間*の何もない隙間です。**横方向の隙間**は、端から端まで紙である行を取り除き、**横方向と縦方向の隙間**は、列も取り除きます。ページの縁から 1% 以内にある隙間は取り除かれず、コマ同士がくっつかないように、どの隙間にも細い帯が残ります。トリミングの強さはこれには効きません。しきい値は固定です。

何もない部分が長く続く、ウェブトゥーン形式のページ向けです。例では、_Pepper&Carrot_ の 3 ページを、[読み方](../reading/#内容)と同じように 1 本の縦長のストリップにつなぎ、**ウェブトゥーンの縦長ストリップ**として変換して、結果の 2 ページ目を示しています。どの画像も、左がそのページで、取り除かれた行と列をピンクで塗っています。右は残ったページで、同じ縮尺です。

最後の画像では、右の縁に沿った帯も取り除かれていますが、これはコマの間の隙間ではありません。列については、縁の 1% はページの幅ではなく高さを基準に測ります。KCC がそうしていて、mangapress もそれに従っているためです。そのため、幅より高さのあるページでは、右の縁に沿った白い帯は隙間と同じように取り除かれ、左の縁に沿ったものは残ります。

`--ipc` は `disabled`、`horizontal`、`both` を受け付けます。
